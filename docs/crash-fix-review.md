# v1.2.1 崩溃修复与代码复查

设备反馈：Xiaomi 17 Pro、第五代骁龙 8 至尊版、Android 16、HyperOS 3.0.319.0.WBLCNXM.C11。没有收到设备日志，也没有连接该真机。

## 证据与修复

1. 原依赖 ONNX Runtime 1.23.2 有已知的 SM8850／Android 16 SIGILL 问题。上游维护者解释与不适用的 SME1／SME2 指令及 CPU 能力检测有关，报告者确认原生 1.24.4 不再复现。由于 Maven Central 没有发布 1.24.4 的 Android／Java 包，应用与桌面回归统一升级为 1.25.1。依据：[Microsoft #27884](https://github.com/microsoft/onnxruntime/issues/27884)、[官方 Maven 元数据](https://repo.maven.apache.org/maven2/com/microsoft/onnxruntime/onnxruntime-android/maven-metadata.xml)。这是与反馈高度匹配的已知兼容性问题，不能替代该设备的实际崩溃栈。
2. 原生信号不能被 Kotlin 的 `try/catch` 捕获。将模型加载和推理移入 `android:process=":semantic"` 的非导出服务，主进程仅通过私有 AIDL 请求 512 维向量。服务死亡变为可处理的 Binder 断开；解除绑定并停止本次运行内的重新连接，保留已有其他模式结果，避免反复启动崩溃服务。未启用其他模式时明确提示不可用。
3. 复查发现模型缓存原先只验证长度，等长损坏文件可能进入原生解析器。每次进程首次创建模型前验证大小和完整 SHA-256，不符合时从内置资源重建并验证；临时文件在失败后清理。
4. 复查发现 `Float.NaN.coerceIn()` 仍可能保留 NaN；现在读写字号均先检查有限值，防止无效字号进入文字布局。
5. 对服务连接超时、断开、取消与关闭路径复查：原生调用不阻塞 UI 线程，外层取消不破坏下一次连接，清理等待在途推理完成，已被系统移除的绑定不会在解绑时再次抛到主线程。遥测显式关闭。
6. 增加本机 Java 未捕获异常记录和 Android 11+ 系统退出信息导出。安装异常处理器后仍调用系统原处理器；不会尝试吞掉不可恢复的进程错误。只保留近期四个本地异常文件，导出通过有临时读取权限的 FileProvider 和系统分享面板，不自动联网发送。

## 验证范围

- 最终自动回归共 48 项，全部通过；Lint 0 错误、11 个警告（KTX 写法建议和依赖版本提示）。
- Android 15／16 的 Robolectric Compose 流程回归：启动、句意和多模式搜索、圣经与古兰经切换、中阿对照、阅读、收藏、主题、更新提示；真实 ONNX 模型回归仍读取内置完整索引。
- 故障注入：`DeadObjectException` 后主查询仍返回关键词结果，后续查询不重启死亡服务；服务断开、查询取消、解绑与服务私有进程声明；等长损坏模型自动恢复；无效字号和诊断文件内容。
- 发布附件 `verification.json` 记录最终测试数量、Lint 结果、APK 与源码哈希、签名和 16 KB 对齐检查。
- 没有 Xiaomi 真机验证。Windows 模拟器缺少可用硬件加速，软件模拟未成功启动，因此不计作设备测试。Windows 的 FileProvider 主机路径与 Android Unix 路径不同，本地自动测试验证诊断记录与报告内容，未将系统分享面板列为已验证功能。

## 兼容性与剩余边界

包名和证书保持一致，可覆盖 v1.0／v1.1／v1.2，保留本机收藏和设置。完整文本、章节编号、模型文件及既有向量均不改变。

独立服务仍共享应用 UID，不能保证抵御系统级低内存杀进程或设备 GPU／系统组件崩溃；服务初始化或推理的额外内存和 IPC 成本是本次隔离的代价。原生退出的栈不能由 Java 处理器保存，系统退出原因可能因厂商策略或保留期限而不可用。该版本不宣称已在报告设备上复现或彻底排除全部原因。
